Conceito Central

A Ilusão da Janela: Terminal vs. Shell

Por que chamamos a mesma janela preta por nomes diferentes?

O Terminal Físico (1978)

O DEC VT100 não tinha CPU própria. Apenas lia teclas, enviava por cabo serial e desenhava texto na tela de fósforo.

O Emulador Moderno vs. O Shell

  • Emulador de Terminal: A janela gráfica (iTerm2, Alacritty, GNOME Terminal, Windows Terminal). Ela virtualiza a tela do VT100.
  • O Shell: O programa que roda do outro lado (Bash, Zsh, Fish). Ele é um interpretador de comandos com linguagem própria.
  • Recebe teclas via stdin, expande variáveis, cria pipes e aciona chamadas de sistema (syscalls) ao kernel.
- Explicar a distinção entre a janela que desenha (terminal) e o processo que interpreta comandos (shell). - Hoje emulamos em software o que antigamente era uma máquina física de 15 kg.
Arquitetura

O Shell como Maestro do Sistema

Como o comando digitado no teclado chega ao processador e ao disco:

- Percorrer o diagrama da esquerda para a direita: - 1. Emulador lê teclado e envia stdin. - 2. Shell analisa sintaxe, busca no PATH, faz expansões e invoca syscalls. - 3. Kernel executa as operações e aciona drivers/hardware. - 4. Retorno verde (stdout/stderr) volta até o terminal.
Estrutura de Arquivos

O Padrão FHS (Filesystem Hierarchy Standard)

Princípios fundamentais e diretórios essenciais:

🌳 4 Princípios do Linux

  • Raiz Única (/): Sem unidades separadas (C:, D:). Tudo brota da raiz /.
  • Case-Sensitive: codigo.c e Codigo.c são arquivos distintos.
  • "Tudo é um arquivo": Dispositivos e métricas são acessados como arquivos.
  • Arquivos Ocultos: Começam com ponto (ex: .bashrc, .git).

📂 Diretórios Vitais da Árvore

  • /bin, /usr/bin: Executáveis do sistema (ls, python3).
  • /home/usuario: Seus arquivos pessoais (~).
  • /etc: Configurações globais do sistema operacional.
  • /dev/null: O "buraco negro" — descarta dados sem erro.
  • /tmp: Arquivos temporários limpos no reboot.
- Enfatizar a raiz única e a diferença entre maiúsculas/minúsculas. - Mencionar que /dev/null será muito útil nos redirecionamentos do Módulo 02.
Prática ao Vivo

Navegação Ágil e Produtividade

Comandos fundamentais e atalhos de terminal:

Comandos Fundamentais

pwd              # Onde estou? (Print Working Dir)
ls -la           # Lista completa (com ocultos)
cd /etc          # Caminho absoluto
cd ..            # Sobe para o diretório pai
cd ~             # Diretório pessoal ($HOME)
cd -             # Alterna para o diretório anterior!

⚡ Superpoderes do Teclado

  • Tab: Autocompleta comandos e caminhos. 2× lista opções.
  • Ctrl + R: Busca reversa no histórico de comandos digitados.
  • Ctrl + C: Interrompe imediatamente o comando (SIGINT).
  • Ctrl + L: Limpa a tela preservando a posição do cursor.
- Dizer explicitamente: use Tab para tudo. Ele previne 95% dos erros de digitação. - Demonstrar Ctrl+R para buscar comandos longos do histórico.
Variáveis de Ambiente

O Mistério do $PATH

Por que o terminal acha ls mas retorna command not found em outros?

Como o Shell Busca Comandos

O shell não vasculha o disco inteiro. Ele consulta a lista de pastas do $PATH da esquerda para a direita:

$ echo $PATH
/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

Se o binário não estiver em nenhum desses diretórios ➔ command not found!

Localizando com which & O Erro Típico 

$ which ls
/bin/ls

$ which python3
/usr/bin/python3
🚨 E o script na pasta atual?

Por segurança, o diretório atual (.) não fica no $PATH. É obrigatório explicitar o caminho: ./script.sh!

- A pergunta clássica do aluno: "Instalei mas não funciona". - Mostrar que o PATH é uma lista separada por dois pontos percorrida da esquerda para a direita.
Segurança

Permissões de Acesso e chmod

Arquivos novos não nascem executáveis por design de segurança:

- Percorrer o diagrama das permissões detalhadamente: - Tipo de arquivo (d = diretório, - = arquivo regular) - Três blocos de rwx: Dono (Usuário), Grupo e Outros - Valores: r = leitura (4), w = escrita (2), x = execução (1) - Demonstrar o fluxo do erro ao vivo no terminal: 1. echo "echo oi" > teste.sh 2. ./teste.sh ➔ Permission denied (bloqueado por padrão!) 3. chmod +x teste.sh 4. ./teste.sh ➔ oi
