Histórico

Uma Breve Viagem no Tempo

Como chegamos ao sistema operacional mais importante do planeta:

1969 • Unix (Bell Labs)

Ken Thompson e Dennis Ritchie criam o Unix. Em 1973 é reescrito em linguagem C, tornando-se o primeiro SO verdadeiramente portátil entre processadores.

1983 • Projeto GNU

Richard Stallman lança a FSF criando ferramentas livres (GCC, utilitários de shell e bibliotecas). Faltava uma peça vital: o Kernel (núcleo).

1991 • Kernel Linux

Linus Torvalds desenvolve o kernel livre e lança sob licença GPL. A união do GNU + Linux cria o ecossistema completo que usamos hoje.

💡 Legado: Do Unix herdamos a modularidade, a portabilidade e a premissa de que sistemas complexos são construídos conectando ferramentas simples.

- A união de ferramentas de usuário (GNU) com o kernel (Linux) explica o termo formal GNU/Linux.
Filosofia

A Filosofia Unix

Três princípios de design que tornam o terminal uma ferramenta imbatível:

1. Especialização

Faça apenas uma coisa e faça-a muito bem. Programas pequenos são mais confiáveis e fáceis de depurar (ex.: grep filtra, sort ordena).

2. Composição

A saída de um comando deve ser a entrada do próximo. O operador *Pipe* (|) permite criar pipelines complexos sem arquivos intermediários em disco.

3. "Tudo é um arquivo"

No Unix/Linux, discos, conexões de rede, teclados e memória (/dev, /proc) são manipulados com as mesmas chamadas de arquivos.

- A filosofia Unix é como blocos de LEGO: comandos simples combinados formam qualquer aplicação de análise de dados.
Arquitetura

O que é o Shell?

A evolução da ponte entre o usuário e o núcleo do sistema operacional:

1. O Terminal Físico

Hardware de 1978 (DEC VT100): teclado e tela de fósforo conectados a um mainframe remoto.

2. O Emulador Moderno

A janela gráfica na sua tela (iTerm2, Alacritty, Terminal).

Ele apenas desenha texto e repassa teclas digitadas, emulando virtualmente o hardware VT100.

3. O Shell (O Maestro)

O interpretador (Bash, Zsh, Fish) que roda dentro da janela.

Interpreta comandos, resolve variáveis e solicita ao Kernel a execução de programas.

Você (Teclado) ➔ Emulador (Janela) ➔ Shell (Interpretador) ➔ Kernel (Hardware/SO)

- Distinção fundamental: o emulador de terminal é a "janela"; o shell é o interpretador de comandos que roda dentro dela.
Estrutura

O Sistema de Arquivos (FHS)

A organização lógica de pastas e regras fundamentais:

🌳 Raiz Única (/)

Sem unidades separadas (C:, D:). Tudo brota da raiz /. Discos e pendrives são montados em pastas dessa árvore.

🔤 Case-Sensitive

Diferencia maiúsculas e minúsculas: relatorio.txt e Relatorio.txt são arquivos totalmente independentes.

Pastas Essenciais da Árvore:

  • /bin, /usr/bin: Programas executáveis.
  • /etc: Configurações do sistema operacional.
  • /home/usuario: Seus arquivos pessoais (~).
  • /dev: Dispositivos de hardware mapeados.
  • /proc: Métricas e processos em tempo real.
  • /tmp: Arquivos temporários (limpos no reboot).
- O padrão FHS (Filesystem Hierarchy Standard) garante consistência entre qualquer distribuição Linux.
Execução

O Superpoder da Variável $PATH

Como o sistema sabe onde está o comando que você digitou?

# O shell busca nos diretórios listados no $PATH, da esquerda para a direita:
$ echo $PATH
/usr/local/bin:/usr/bin:/bin:/usr/sbin

# Para descobrir o caminho exato do binário que será executado:
$ which python3
/usr/bin/python3

$ which gcc
/usr/bin/gcc

💡 Regra de Ouro: Entender o $PATH resolve 80% dos erros de "command not found" ao instalar NodeJS, Python, Java, Rust ou Docker!

- Enfatizar que se um script ou binário local não roda direto sem ./, é porque o diretório atual '.' não fica no $PATH por segurança.
Segurança

Permissões de Acesso (chmod)

Segurança e controle de execução em nível de arquivo:

- r w x  r - x  r - x   1  marcelo  staff   meu_script.sh
  └──┬──┘  └──┬──┘  └──┬──┘
     │        │        └── Outros (o):  leitura + execução (4+0+1 = 5)
     │        └─────────── Grupo (g):    leitura + execução (4+0+1 = 5)
     └──────────────────── Dono (u):     leitura + escrita + execução (4+2+1 = 7)

Cálculo Octal

• r (read) = 4  |  • w (write) = 2  |  • x (exec) = 1
755 = Dono edita e roda; demais só executam.

Tornando Executável

Todo script recém-criado precisa de permissão explícita:
$ chmod +x meu_script.sh
$ ./meu_script.sh

- Explicar por que scripts em Linux não são executáveis por acidente: requerem a flag 'x'.
