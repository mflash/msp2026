Boas Práticas Profissionais

Anatomia de um Script & Modo Estrito

O que diferencia um script amador de um script pronto para produção:

1. O Shebang e o Modo Estrito

#!/bin/bash
# Shebang: informa ao SO qual interpretador usar

set -euo pipefail
# -e: encerra imediatamente se algum comando falhar
# -u: acusa erro fatal se variável não declarada for lida
# -o pipefail: falha no meio de um pipe invalida o todo

Sem set -euo pipefail, um erro no meio do backup passa despercebido!

2. Variáveis e Execução

# Captura saída de comando com $(...)
DATA_HOJE=$(date +%Y-%m-%d)
USUARIO=$(whoami)

echo "Iniciando rotina de $USUARIO em $DATA_HOJE..."

# Executando:
chmod +x meu_script.sh
./meu_script.sh

Por que o ./? Como vimos no Módulo 01, a pasta atual não está no $PATH por segurança.

- Conectar com o Módulo 01: o `./` agora faz sentido porque lembram da variável `$PATH`. - Explicar que scripts sem modo estrito mascaram desastres silenciosos em servidores.

Argumentos e Códigos de Saída

Criando ferramentas CLI profissionais que informam erros corretamente:

Variáveis Especiais de Argumento

  • $1, $2, $3: Primeiro, segundo e terceiro argumentos.
  • $#: Quantidade total de argumentos recebidos.
  • $0: O nome do próprio script invocado.
  • $?: Exit code do último comando (0 = Sucesso, >0 = Erro).

Validando Parâmetros no converter_imagem.sh 

if [[ $# -ne 2 ]]; then
    echo "Uso: $0  " >&2
    exit 1
fi

ARQUIVO="$1"
FORMATO="$2"
echo "Convertendo $ARQUIVO para $FORMATO..."
exit 0

Aviso enviado ao stderr (>&2) e código de saída exit 1!

- Demonstrar no terminal: rodar sem argumentos (`echo $?` dá 1), rodar com 2 argumentos (`echo $?` dá 0). - Conectar com o stderr do Módulo 02.
Controle de Fluxo

Decisões e Laços com Arquivos

Como testar arquivos e processar diretórios com segurança:

Testes de Arquivos com [[ ... ]]

# Espaços dentro dos colchetes são OBRIGATÓRIOS!
if [[ ! -d "$DIR_BACKUP" ]]; then
    echo "Criando diretório de backup..."
    mkdir -p "$DIR_BACKUP"
fi

if [[ -f "$ARQUIVO_CONFIG" ]]; then
    source "$ARQUIVO_CONFIG"
fi

Operadores comuns: -f (arquivo regular), -d (diretório), -s (não vazio), -x (executável).

Iterando sobre Arquivos com Segurança

# Use aspas duplas sempre ao redor de variáveis!
for doc in docs/*.md; do
    echo "Processando: $doc"
    # Aspas evitam que espaços no nome quebrem o comando:
    wc -w "$doc"
done

⚠️ Sem aspas, um arquivo chamado meu relatorio.md vira dois argumentos separados e quebra a rotina!

- Alerta de erro clássico: esquecer o espaço em `[[-f arq]]` faz o Bash procurar um comando chamado `[[-f` e falhar com command not found.
Integração Total

Um Script Real: monitor_saude.sh

Conectando comandos, pipes, processos e lógica condicional:

Extração e Decisão Aritmética

#!/bin/bash
set -euo pipefail

LIMITE_DISCO=80

# 1. Extrai uso do disco com pipe e awk
USO_DISCO=$(df -P / | awk 'NR==2 {print $5}' | tr -d '%')

# 2. Avaliação aritmética com (( ... ))
if (( USO_DISCO >= LIMITE_DISCO )); then
    echo "[ALERTA] Uso de disco crítico: ${USO_DISCO}%!" >&2
    exit 2
else
    echo "[OK] Disco em ${USO_DISCO}%. Operação normal."
    exit 0
fi
- Mostrar como o script junta os módulos anteriores: `df | awk | tr` (Módulo 02), verificação de recursos de hardware (Módulo 03), e script com shebang e códigos de saída (Módulo 04).

Agendamento com cron

Executando rotinas periodicamente em servidores sem intervenção humana:

A Sintaxe dos Cinco Campos do crontab -e

*
Minuto
(0-59)
*
Hora
(0-23)
*
Dia do Mês
(1-31)
*
Mês
(1-12)
*
Dia da Semana
(0-7)

Exemplo de Produção: Monitor a cada 15 minutos

# Edita as tarefas do usuário atual:
crontab -e

# Executa o script a cada 15 min e grava saída e erro em log:
*/15 * * * * /home/marcelo/scripts/monitor_saude.sh >> $HOME/logs/saude.log 2>&1

Lê-se: "A cada 15 minutos, rode o monitor_saude.sh e anexe stdout e stderr ao arquivo saude.log."

- Fechar o ciclo: o script não depende de ninguém logar para rodar. - Relembrar o `>>` e `2>&1` do Módulo 02.
